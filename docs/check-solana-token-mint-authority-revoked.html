How to check if a Solana token's mint authority is revoked

"Mint authority revoked" means nobody can ever print more of the token. "Freeze authority revoked" means nobody can freeze your tokens in your wallet. Both are fields on the token's mint account, and you can read them yourself with one RPC call, no explorer and no API key.

What the two authorities can do

FieldIf set, its holder canRevoked looks like
mintAuthorityMint any amount of new tokens, diluting every holdernull
freezeAuthorityFreeze any token account, so its owner cannot sell or move itnull

A memecoin that still has either one live is a risk. A regulated stablecoin like USDC keeps both on purpose. The field is the fact; what it means depends on who holds it.

Working code, zero dependencies

getAccountInfo with encoding: "jsonParsed" decodes the mint for you. Save as check-mint.mjs and run node check-mint.mjs <mint>. The free public mainnet RPC serves this method, so no key is needed.

// check-mint.mjs: node check-mint.mjs <mint>. Node 20+, no dependencies
const RPC = process.env.SOLANA_RPC_URL || "https://api.mainnet-beta.solana.com";
const mint = process.argv[2] ?? "DezXAZ8z7PnrnRJjz3wXBoRgixCa6xjnB7YaB1pPB263"; // BONK

const res = await fetch(RPC, {
  method: "POST",
  headers: { "content-type": "application/json" },
  body: JSON.stringify({ jsonrpc: "2.0", id: 1, method: "getAccountInfo", params: [mint, { encoding: "jsonParsed" }] }),
});
const { result, error } = await res.json();
if (error) throw new Error(`RPC error ${error.code}: ${error.message}`);
const parsed = result.value?.data?.parsed;
if (parsed?.type !== "mint") throw new Error("not a token mint");

const { mintAuthority, freezeAuthority, supply, decimals } = parsed.info;
console.log("program:         ", result.value.data.program); // "spl-token" or "spl-token-2022"
console.log("mint authority:  ", mintAuthority ?? "revoked");
console.log("freeze authority:", freezeAuthority ?? "revoked");
console.log("supply:          ", supply, "raw units,", decimals, "decimals");

// Token-2022 mints can carry more powers than the two classic authorities
for (const ext of parsed.info.extensions ?? []) {
  if (["permanentDelegate", "transferFeeConfig", "transferHook", "mintCloseAuthority", "pausableConfig"].includes(ext.extension)) {
    console.log("extension:       ", ext.extension, JSON.stringify(ext.state));
  }
}

BONK has both authorities revoked. USDC and PYUSD (PayPal USD) keep theirs, as issuers of regulated stablecoins do.

Token-2022: revoked is not the whole story

Mints owned by the Token-2022 program can carry extensions with powers the two classic fields do not show. For a rug check, look at these too:

  • permanentDelegate: an address that can transfer or burn tokens from any holder's account. On a memecoin, that is a worse power than a mint authority.
  • transferFeeConfig: a fee in basis points taken on every transfer, which its authority can raise (up to 100%) for later epochs.
  • transferHook: a program that runs on every transfer and can make transfers fail. programId: null, as on PYUSD above, means none is set.
  • pausableConfig and defaultAccountState: transfers can be paused, or new accounts start frozen.
  • mintCloseAuthority: the mint account itself can be closed once supply is zero.

Where pump.fun coins stand

pump.fun creates coins with the mint and freeze authority already revoked, so for those the check mostly confirms it. The question that matters there is who holds the supply, not who can mint more. Coins launched elsewhere, and any token someone sends you, are worth checking.

Many mints at once, with metadata

solana-token-meta reads the mint and its Metaplex metadata together, 50 mints per getMultipleAccounts call, decodes every Token-2022 extension, and returns the facts above as booleans:

npm install github:blixvip/solana-token-meta
import { getTokenMetas, riskFlags } from "solana-token-meta";

const metas = await getTokenMetas([
  "DezXAZ8z7PnrnRJjz3wXBoRgixCa6xjnB7YaB1pPB263", // BONK
  "EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v", // USDC
  "DxYWLXgKJpQmfhTG7ikK6oX6oDhxMhN5wCs5BJekpump", // a pump.fun coin on Token-2022
]);
for (const m of metas) {
  const f = riskFlags(m);
  console.log(m.metadata?.symbol, m.program, "mint:", f.mintAuthorityActive ? "ACTIVE" : "revoked", "freeze:", f.freezeAuthorityActive ? "ACTIVE" : "revoked", "metadata mutable:", f.metadataMutable);
}
Bonk spl-token mint: revoked freeze: revoked metadata mutable: true
USDC spl-token mint: ACTIVE freeze: ACTIVE metadata mutable: true
DEED token-2022 mint: revoked freeze: revoked metadata mutable: false

riskFlags(m) also has hasPermanentDelegate, hasTransferFee, hasTransferHook, nonTransferable, defaultAccountsFrozen and paused. Or from a terminal: npx github:blixvip/solana-token-meta <mint>.

Limits to know

  • Revoked authorities do not make a token safe. Concentrated holders, a pulled liquidity pool or a mutable name can still hurt you. For holder concentration, see how to calculate the top 10 holders percentage.
  • Who holds an active authority matters. A multisig of a known issuer and a fresh wallet look the same in this field.
  • Mutable metadata means the name, symbol and image can still be changed by the update authority. That is a separate field, in the Metaplex account or the Token-2022 metadata extension.
